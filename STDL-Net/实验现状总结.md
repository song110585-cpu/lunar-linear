## Scene-Level 划分方案 (v8)

### 问题诊断
- 旧方案(v6): 从 train 随机抽取 10% tile 做 val → **数据泄漏**
- 同一 Scene 的相邻 tile 共享光照/纹理/地质特征 → val 虚高 0.68 vs test 0.40
- v7 的教训: train 完全不含 Mare → 域迁移太大, 模型不会 Mare 样式
- **根因: 需要 Scene 隔离, 但 train 必须保留一部分 Mare**

### 当前方案: Mare Serenitatis 内按行切分 (split_row=6447)

```
Mare Serenitatis 网格:
┌──────────────────────┐
│  rows < 6447         │ → Val (256 tiles, WR 丰富)
│  (低行号, WR 密集)    │
├──────────────────────┤
│  rows >= 6447        │ → Train (227 tiles, Graben 丰富)
│  (高行号, Graben 密集) │
└──────────────────────┘
```

- **Train**: Mare 高行号(227) + 其余 22 Scene(1370) = 1597 tiles
- **Val**: Mare 低行号(256) = 256 tiles (13.6%)
- **Test**: Mare 独立区域(331 tiles), 完全不参与训练
- Catena-* Scene(19个, 364 tiles)全部为纯背景
- 划分脚本: `STDL-Net/scripts/split_by_scene.py`
- Split 文件: `dataset_analysis/valid_tiles_train_scene.txt` / `valid_tiles_val_scene.txt`

### Graben 域迁移问题 (关键发现)

Train 的 Graben 像素分布:
| Scene | Graben 占比 | 特征 |
|-------|------------|------|
| Rima Ariadaeus | 73% | Rima 式 Graben |
| Mare Serenitatis 上半 | 24% | **Mare 式 Graben** |
| 其他 | 3% | - |

Val/Test 是 100% Mare → **模型学的 Graben 主要是 Rima 风格, 拿到 Mare 上不认**。
这是 v6→v8 迁移的核心难点, 不是 split 设计的问题——反而说明 Scene Split 正确暴露了真实泛化水平。

### 混淆矩阵关键发现

- **Background → Graben**: 24% (841万px) — 模型在 test 上把大量背景判为 Graben, 假阳性严重
- **Fault → Rille**: 58% — 256 尺度下两类纹理混淆

### 根因

1. **256×256 上下文不足**: 感受野仅 512 的 1/4, 线性构造整体形态丢失
2. **Val-Test 分布不匹配**: Val 背景过多(98.3%), 选出的 best checkpoint 在 test 前景密集区表现差
3. **仅 16 epoch**: patience=20 过早触发, 模型未充分收敛

## 关键发现：简单模型 + 全量训练 > 复杂模型 + Val 选优

### R17 vs R46 对比

| | R17 | R46 |
|---|---|---|
| 模型 | **small** | base |
| Loss | CE+Dice | CE+Dice |
| Val | 无 | 5% 随机 |
| Train量 | v5 全量 | v5 95% |
| Test mIoU | **0.53** | 0.496 |

**加了 base 模型、class_weights、5% val 抽走数据，结果反而退步。**

之前所有实验(R34-R46)都用 val 选 best checkpoint，但 val 要么泄漏(虚高)要么跨域(选错)。选出来的"最优"可能根本不是 test 上的最优。

### 新策略

- **Val**: 保留 5% 随机 val，仅用于 loss 监控和早停（避免训练崩溃），**不用于选 best checkpoint**
- **Test**: 每 10 epoch 测一次，test mIoU 最高的那个 epoch 就是最终模型
- **优化方式**: 从 R17 基线开始，**每次只改一个变量**，test 判断保留还是回退

### 优化路线

```
R48: small + CE+Dice + v5 全量 + 100epoch → 目标 test ≥ 0.53 (复现 R17)
  ↓
R49: + class_weights [0.15,1.0,1.3,1.8,2.5]
  ↓
R50: + weighted tile sampling (tile_sample_exp=0.3)
  ↓
R51: 换 base 模型
  ↓
R52: + Graben 形态增强
```

每轮只改一个变量，test 判断保留还是回退。

## 未来方向: 双分支架构 (检测→分类)

### 思路

参考 Yan 等人两阶段思路, 一个分支做二分类(识别线性), 另一个分支给线性贴标签(多分类).

### 为什么适合本任务

| 当前单分支问题 | 双分支解法 |
|---------------|-----------|
| Graben 漏检 (Recall 42%) | 分支1 只管"有线没线", 不计类别, Recall 自然高 |
| Fault→Rille 混淆 | 分支2 只在线性区域做分类, 干扰减少 |
| Background 98% 压倒 | 分支1 做二分类, 正负样本比大幅改善 |

### 架构设计

```
SwinV2 Backbone (共享, 不改)
    ├── FPN Decoder → [1ch] 分支1: BCE+Dice → 前景/背景
    └── Gate(× sigmoid) → FPN Decoder → [4ch] 分支2: CE(仅GT>0像素) → WR/Rille/Fault/Graben
```

- 分支1 解码器: `smp.UnetDecoder` (轻量, 开源)
- 分支2 用分支1 的 sigmoid 做 attention gate, 只看高概率区域
- 最终输出 = 分支2 × 分支1 (背景自动归零)

### 可复用开源组件

| 组件 | 来源 |
|------|------|
| SwinV2 backbone | 现有代码, 不改 |
| UnetDecoder | `segmentation-models-pytorch` |
| FPN+PAN | 现有 `swinv2unet.py` |
| BCE+Dice Loss | 现有实现 / `smp.losses` |

> 先跑完 R50-53 确认单分支天花板, 再决定是否动手实现.

### 切分策略

| 参数 | 值 | 说明 |
|------|-----|------|
| TILE_SIZE | 512 | 恢复 512, v9-256 已证明上下文不足 |

| BACKGROUND_KEEP_VALTEST | 0.3 | val/test 同样, 降低背景压倒性占比 |

### 区域划分 (地理坐标)

- **Mare Serenitatis**: 按纬度 Y 横切
  - Y > 27.53° → train
  - 22.52° < Y ≤ 27.53° → val
  - Y ≤ 22.52° → test
- **Rima Ariadaeus**: 按经度 X 竖切
  - X ≤ 14.67° → train
  - 14.67° < X ≤ 17.07° → val
  - X > 17.07° → test
- **其他区域**: 随机 10% val / 90% train
- `test_` 前缀文件 → 强制 test
