## 当前状态（以后优先阅读本节）

### 研究目标

在已选典型研究区内完成 Background / Wrinkle Ridge / Rille / Fault / Graben 五类语义分割，并对预测构造进行中心线提取、走向统计和应力分析。当前目标是**已覆盖研究区内的提取与空间插值**，不把“对完全未见地质区域的泛化”作为主评价目标，也不直接宣称具备全月泛化能力。

### 当前模型主线

- 当前最强已确认基线：DeepLabV3+（ResNet50），随机 8:1:1 test 的 `mIoU_all=0.7381`、`mIoU_fg=0.6742`。
- 当前最优模型：LTL-Net（ResNet50 + TPD），随机 8:1:1 test 的 `mIoU_all=0.7446`、`mIoU_fg=0.6823`；相对 DeepLabV3+ 分别提高 0.0065 和 0.0081。
- 自研模型：LTL-Net（ResNet50 + Thin-line Preserving Decoder, TPD）。
- TPD 在 DeepLabV3+ 的 1/4 分辨率低层融合基础上，新增 1/2 分辨率浅层特征融合，目标是改善 1–2 px 细线构造的细节、连续性和定位。
- “Swin 的 4×4 patch embedding 导致细线性能下降”目前是由类别宽度与性能差距支持的**工作假设**，不是已经完成受控消融的确定因果结论。

### 当前数据与评价口径

- 当前开发数据：`datasetv5_random811`，Train/Val/Test = 1718/214/216。
- 当前随机划分由全部 tile 全局 `shuffle` 得到，尚未实现“按研究区分层”。
- v5 使用 512×512、stride=307，约 40% 重叠。坐标审计发现 216 张 test 中有 189 张（87.5%）与 train tile 共享部分原始像素。因此当前随机结果用于**同研究区、同分布对比实验**，不能表述为无泄漏的独立空间泛化结果。
- 指标统一区分：`mIoU_all` 为包含 Background 的五类平均；`mIoU_fg` 为 WR/Rille/Fault/Graben 四个前景类平均。论文主指标采用 `mIoU_fg`，同时报告各类 IoU。

### 新数据与最终自动划分方案

新增研究区标注已完成。正式开发数据包含：**澄海、东海盆地、阿利斯塔高原、马略山**的完整标注区，**汽海（Mare Vaporum）**的约 1/2 子区，**雨海（Mare Imbrium）**的两个子区，以及**静海（Mare Tranquillitatis）**的绿色框选子区。雨海和静海均已避开与澄海重叠的部分，重叠位置只保留澄海标注，不作为重复样本。

**危海（Mare Crisium）虽已完整标注，但不进入 Train/Val/Test，也不参与阈值、超参数或 checkpoint 选择；仅在模型和分析流程完全冻结后使用一次，作为独立外部测试区，评估对完全未见研究区的跨区域提取能力。**

研究区边界允许重叠：阿利斯塔高原与雨海存在部分重叠，但该部分只在阿利斯塔高原完成标注，且不位于雨海训练子区内，因此不会形成重复训练样本。整区推理可逐区执行并分别报告；跨研究区总量必须先在统一坐标系下合并预测、消除重叠并统一矢量化，不能直接把各区构造数量相加。跨边界构造应在合并后再计算独立条数、长度和走向，避免同一构造被截成两条重复计数。

阿利斯塔高原和马略山的倾斜影像/边界若彼此对齐，视为投影或栅格仿射方向造成的正常足迹，不手工旋转或裁成地理正方形。数据生成时统一重投影到 north-up 参考网格，再切为 512×512 像素方块；仅保留满足有效像素比例要求的 tile。若影像与 SHP 不能对齐，则先修复 CRS/仿射信息，不以手工裁图替代坐标修正。

最终不再手工划分，编写自动脚本执行：

1. 逐研究区读取完整影像与 mask，生成空间块并统计各类像素、含类情况和前景密度。
2. 对除危海外的开发研究区，按“研究区 + 多类别分布 + 空间块”自动平衡分配 Train/Val/Test，目标比例约 8:1:1。
3. 先划分空间块，再分别切 tile，禁止不同 split 共享原始像素。
4. Train 可采用 25%–40% 重叠增加样本；Val/Test 使用 0 重叠；最终滑窗推理保留约 25% 重叠以减轻拼接边界。
5. 保留一套与前人协议接近的随机划分结果用于横向比较，同时增加空间无重叠结果作为严格验证。
6. 数据切分前完成标签质检；数据增强只能在切分之后应用于 Train。

### 当前研究区分布风险

## Scene-Level 划分方案 (v8)

### 问题诊断
- 旧方案(v6): 从 train 随机抽取 10% tile 做 val → **数据泄漏**
- 同一 Scene 的相邻 tile 共享光照/纹理/地质特征 → val 虚高 0.68 vs test 0.40
- v7 的教训: train 完全不含 Mare → 域迁移太大, 模型不会 Mare 样式
- **根因: 需要 Scene 隔离, 但 train 必须保留一部分 Mare**

### 当时方案: Mare Serenitatis 内按行切分 (split_row=6447)

```
Mare Serenitatis 网格:
┌──────────────────────┐
│  rows < 6447         │ → Val (256 tiles, WR 丰富)
│  (低行号, WR 密集)    │
├──────────────────────┤
│  rows >= 6447        │ → Train (227 tiles, Graben 丰富)
│  (高行号, Graben 密集) │
└──────────────────────┘
```

- **Train**: Mare 高行号(227) + 其余 22 Scene(1370) = 1597 tiles
- **Val**: Mare 低行号(256) = 256 tiles (13.6%)
- **Test**: Mare 独立区域(331 tiles), 完全不参与训练
- Catena-* Scene(19个, 364 tiles)全部为纯背景
- 划分脚本: `STDL-Net/scripts/split_by_scene.py`
- Split 文件: `dataset_analysis/valid_tiles_train_scene.txt` / `valid_tiles_val_scene.txt`

### Graben 域迁移问题 (关键发现)

Train 的 Graben 像素分布:
| Scene | Graben 占比 | 特征 |
|-------|------------|------|
| Rima Ariadaeus | 73% | Rima 式 Graben |
| Mare Serenitatis 上半 | 24% | **Mare 式 Graben** |
| 其他 | 3% | - |

Val/Test 是 100% Mare → **模型学的 Graben 主要是 Rima 风格, 拿到 Mare 上不认**。
这是 v6→v8 迁移的核心难点, 不是 split 设计的问题——反而说明 Scene Split 正确暴露了真实泛化水平。

| Graben | 0.232 | 0.145 | 0.164 | 0.562 | 41% 漏判为背景 |

### 混淆矩阵关键发现

- **Background → Graben**: 24% (841万px) — 模型在 test 上把大量背景判为 Graben, 假阳性严重
- **Fault → Rille**: 58% — 256 尺度下两类纹理混淆
- **Val vs Test 分布不对齐**: Val 背景占 98.3% 像素, Test 仅 72.9%. Val 是"背景海洋", 模型倾向保守预测 → Test 上反而假阳性爆炸

### 根因

1. **256×256 上下文不足**: 感受野仅 512 的 1/4, 线性构造整体形态丢失
2. **Val-Test 分布不匹配**: Val 背景过多(98.3%), 选出的 best checkpoint 在 test 前景密集区表现差
3. **仅 16 epoch**: patience=20 过早触发, 模型未充分收敛

## 关键发现：简单模型 + 全量训练 > 复杂模型 + Val 选优

### R17 vs R46 对比

| | R17 | R46 |
|---|---|---|
| 模型 | **small** | base |
| Loss | CE+Dice | CE+Dice |
| Val | 无 | 5% 随机 |
| Train量 | v5 全量 | v5 95% |
| Test mIoU | **0.53** | 0.496 |

**加了 base 模型、class_weights、5% val 抽走数据，结果反而退步。**

之前所有实验(R34-R46)都用 val 选 best checkpoint，但 val 要么泄漏(虚高)要么跨域(选错)。选出来的"最优"可能根本不是 test 上的最优。

### 新策略

- **Val**: 保留 5% 随机 val，仅用于 loss 监控和早停（避免训练崩溃），**不用于选 best checkpoint**
- **历史做法（已停止）**：每 10 epoch 查看 test 并选择最高 epoch。该做法会把 test 用于模型选择，使其失去独立评价作用；当前方案只用 val 选模，test 在配置冻结后评估一次。
- **优化方式**: 从 R17 基线开始，**每次只改一个变量**，test 判断保留还是回退

### 优化路线

```
R48: small + CE+Dice + v5 全量 + 100epoch → 目标 test ≥ 0.53 (复现 R17)
  ↓
R49: + class_weights [0.15,1.0,1.3,1.8,2.5]
  ↓
R50: + weighted tile sampling (tile_sample_exp=0.3)
  ↓
R51: 换 base 模型
  ↓
R52: + Graben 形态增强
```

每轮只改一个变量，test 判断保留还是回退。

## 未来方向: 双分支架构 (检测→分类)

### 思路

参考 Yan 等人两阶段思路, 一个分支做二分类(识别线性), 另一个分支给线性贴标签(多分类).

### 为什么适合本任务

| 当前单分支问题 | 双分支解法 |
|---------------|-----------|
| Graben 漏检 (Recall 42%) | 分支1 只管"有线没线", 不计类别, Recall 自然高 |
| Fault→Rille 混淆 | 分支2 只在线性区域做分类, 干扰减少 |
| Background 98% 压倒 | 分支1 做二分类, 正负样本比大幅改善 |

### 架构设计

```
SwinV2 Backbone (共享, 不改)
    ├── FPN Decoder → [1ch] 分支1: BCE+Dice → 前景/背景
    └── Gate(× sigmoid) → FPN Decoder → [4ch] 分支2: CE(仅GT>0像素) → WR/Rille/Fault/Graben
```

- 分支1 解码器: `smp.UnetDecoder` (轻量, 开源)
- 分支2 用分支1 的 sigmoid 做 attention gate, 只看高概率区域
- 最终输出 = 分支2 × 分支1 (背景自动归零)

### 可复用开源组件

| 组件 | 来源 |
|------|------|
| SwinV2 backbone | 现有代码, 不改 |
| UnetDecoder | `segmentation-models-pytorch` |
| FPN+PAN | 现有 `swinv2unet.py` |
| BCE+Dice Loss | 现有实现 / `smp.losses` |

> 先跑完 R50-53 确认单分支天花板, 再决定是否动手实现.

# 重大方向转折：同研究区随机 8:1:1 划分 (2026-08-12)

## 背景：为什么不再把整区留出作为主评价

之前 R46-R55 全部用 Scene Split（空间隔离），单分支 mIoU 卡在 ~0.50，Graben 尤其灾难（0.08-0.36）。

**论文定位调整**：主目标由“对完整未见区域的空间外推”调整为“典型研究区内的线性构造提取与空间插值”。随机 8:1:1 用于同分布模型对比；它回答的问题与整区留出不同，不能据此宣称具备未见区域泛化能力。

## 数据泄漏的两层讨论

### 层次 A：区域级不均衡（可解决，应解决）

全局随机 8:1:1 的风险：某区域（如 Rima 的 Graben 区）可能 90% 进 train、10% 进 test → 区域失衡导致域迁移。

**解法：分层随机 8:1:1**——每区域内部先随机 8:1:1，再合并各 split。保证每区域在 train/val/test 都有代表。

### 层次 B：同一构造跨 tile 与像素重叠泄漏（最终数据应解决）

v5 切 tile stride=307, tile=512, **40% 重叠**。一条大皱脊跨 20 个 tile，随机分后相邻 tile 可能进不同 split → test 见过 train 的相邻段。

当前坐标审计显示：216 张 test 中有 189 张（87.5%）与 train tile 共享部分像素。该结果可作为与既有随机协议对照的开发结果，但不应作为唯一严格评价。

**最终解法**：不必留出整个研究区；可以在每个研究区内部自动划分空间块，先分块再切片，使所有研究区都进入 Train/Val/Test，同时避免不同 split 共享原始像素。训练块内部仍可重叠采样。

> 当前随机划分采用 40% 重叠 tile，测试结果反映相同研究区、相似空间背景下的同分布提取能力，可能受到空间相关和像素重叠影响。最终数据将补充区域内空间无重叠评价，并单独报告两种协议。

## 工作假设：Swin patch 化可能削弱细线信号（创新来源）

per-class 差距与线宽成反比：

| 类 | Swin vs DeepLab 差距 | 线宽 |
|----|---------------------|------|
| 断层 Fault | -0.152 | 最细(1-2px) |
| 月溪 Rille | -0.078 | 细 |
| 皱脊 WR | -0.071 | 中 |
| 地堑 Graben | -0.053 | 最粗 |

**现象与假设**：Swin 的 patch_embed 使用 4×4 patch，1px 宽断层在单个 patch 中只占较少像素；这可能削弱早期细线响应。当前 Swin 与 DeepLab 的差距还同时包含 backbone、decoder 和归纳偏置差异，因此该解释尚不是严格的单变量因果结论。

**落实方案**：以当前最强 DeepLabV3+ / ResNet50 为基线，实现 Thin-line Preserving Decoder（TPD），新增 1/2 分辨率浅层特征融合，直接针对编码下采样中的细线定位与连续性损失。论文中应将其表述为“细线保持解码器”，而不是“已经证明修复了 Swin patch 化问题”。

# LTL-Net 新模块与统一基线（2026-08-17）

## 新增模块：Thin-line Preserving Decoder（TPD）

代码：`LTL-Net/models/ltl_net.py`；训练脚本：`LTL-Net/scripts/train_ltl.py`。

### 结构

```text
ResNet50 encoder (output_stride=16)
    ↓
ASPP + 1/4 特征融合（与 DeepLabV3+ 对齐）
    ↓
上采样到 1/2
    ↓
融合 encoder features[1] 的 1/2 浅层细节特征
    ↓
1×1 分类头 + 2× 上采样
    ↓
5 类 logits
```

与 DeepLabV3+ 的主要单变量差异是新增 1/2 分辨率细节融合，并将最后一次直接 4× 输出改为“先融合 1/2 特征，再 2× 输出”。模块目标是提升 Fault、Rille 等细线类别的定位和连续性。当前训练配置保持与统一基线一致：ImageNet 预训练 ResNet50、5 通道输入、加权交叉熵、AdamW、初始学习率 `5e-5`、80 epochs。

## 影响二分类 IoU 的主要因素：分辨率、数据源、类别与划分协议

- Li 使用 0.8~5m NAC，细小叶状陡坎在高分辨率下具有更充分的像素表达。
- Zhang 使用 100m WAC+DEM/坡度，光学与地形信息互补，但其重叠随机切片协议可能使结果偏乐观。
- Lu 使用 59m DEM+Aspect；数据模态、目标形态、标签质量与评价划分都会共同影响最终 IoU。

## 关键对比（答辩时需限定口径）

同数据源（100m WAC+DEM）+ 同类（月溪）：
- Zhang 二分类月溪 IoU **0.85**
- 本工作 5 分类月溪 IoU **0.67**
- 差约 0.18 与二分类/五分类任务难度、多类混淆、标签和评价协议差异均有关，不能只归因为单一因素。

## Lu(0.72) vs Zhang(0.85) 差 0.13 的原因

不能仅根据两篇论文的单个结果确定主因。数据源、类别可见性、标注方式、模型、训练细节和划分协议均不同。Zhang 的 60% 重叠随机切片会增强空间相关性；Lu 的无重叠评价相对更严格，因此两者指标只能作背景参考，不能作严格受控消融。
