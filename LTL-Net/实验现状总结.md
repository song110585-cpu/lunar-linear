## Scene-Level 划分方案 (v8)

### 问题诊断
- 旧方案(v6): 从 train 随机抽取 10% tile 做 val → **数据泄漏**
- 同一 Scene 的相邻 tile 共享光照/纹理/地质特征 → val 虚高 0.68 vs test 0.40
- v7 的教训: train 完全不含 Mare → 域迁移太大, 模型不会 Mare 样式
- **根因: 需要 Scene 隔离, 但 train 必须保留一部分 Mare**

### 当前方案: Mare Serenitatis 内按行切分 (split_row=6447)

```
Mare Serenitatis 网格:
┌──────────────────────┐
│  rows < 6447         │ → Val (256 tiles, WR 丰富)
│  (低行号, WR 密集)    │
├──────────────────────┤
│  rows >= 6447        │ → Train (227 tiles, Graben 丰富)
│  (高行号, Graben 密集) │
└──────────────────────┘
```

- **Train**: Mare 高行号(227) + 其余 22 Scene(1370) = 1597 tiles
- **Val**: Mare 低行号(256) = 256 tiles (13.6%)
- **Test**: Mare 独立区域(331 tiles), 完全不参与训练
- Catena-* Scene(19个, 364 tiles)全部为纯背景
- 划分脚本: `STDL-Net/scripts/split_by_scene.py`
- Split 文件: `dataset_analysis/valid_tiles_train_scene.txt` / `valid_tiles_val_scene.txt`

### Graben 域迁移问题 (关键发现)

Train 的 Graben 像素分布:
| Scene | Graben 占比 | 特征 |
|-------|------------|------|
| Rima Ariadaeus | 73% | Rima 式 Graben |
| Mare Serenitatis 上半 | 24% | **Mare 式 Graben** |
| 其他 | 3% | - |

Val/Test 是 100% Mare → **模型学的 Graben 主要是 Rima 风格, 拿到 Mare 上不认**。
这是 v6→v8 迁移的核心难点, 不是 split 设计的问题——反而说明 Scene Split 正确暴露了真实泛化水平。

### 混淆矩阵关键发现

- **Background → Graben**: 24% (841万px) — 模型在 test 上把大量背景判为 Graben, 假阳性严重
- **Fault → Rille**: 58% — 256 尺度下两类纹理混淆

1. **256×256 上下文不足**: 感受野仅 512 的 1/4, 线性构造整体形态丢失
2. **Val-Test 分布不匹配**: Val 背景过多(98.3%), 选出的 best checkpoint 在 test 前景密集区表现差
3. **仅 16 epoch**: patience=20 过早触发, 模型未充分收敛

## 关键发现：简单模型 + 全量训练 > 复杂模型 + Val 选优

### R17 vs R46 对比

| | R17 | R46 |
|---|---|---|
| 模型 | **small** | base |
| Loss | CE+Dice | CE+Dice |
| Val | 无 | 5% 随机 |
| Train量 | v5 全量 | v5 95% |
| Test mIoU | **0.53** | 0.496 |

**加了 base 模型、class_weights、5% val 抽走数据，结果反而退步。**

之前所有实验(R34-R46)都用 val 选 best checkpoint，但 val 要么泄漏(虚高)要么跨域(选错)。选出来的"最优"可能根本不是 test 上的最优。

### 新策略

- **Val**: 保留 5% 随机 val，仅用于 loss 监控和早停（避免训练崩溃），**不用于选 best checkpoint**
- **Test**: 每 10 epoch 测一次，test mIoU 最高的那个 epoch 就是最终模型
- **优化方式**: 从 R17 基线开始，**每次只改一个变量**，test 判断保留还是回退

### 优化路线

```
R48: small + CE+Dice + v5 全量 + 100epoch → 目标 test ≥ 0.53 (复现 R17)
  ↓
R49: + class_weights [0.15,1.0,1.3,1.8,2.5]
  ↓
R50: + weighted tile sampling (tile_sample_exp=0.3)
  ↓
R51: 换 base 模型
  ↓
R52: + Graben 形态增强
```

每轮只改一个变量，test 判断保留还是回退。

## 未来方向: 双分支架构 (检测→分类)

### 思路

参考 Yan 等人两阶段思路, 一个分支做二分类(识别线性), 另一个分支给线性贴标签(多分类).

### 为什么适合本任务

| 当前单分支问题 | 双分支解法 |
|---------------|-----------|
| Graben 漏检 (Recall 42%) | 分支1 只管"有线没线", 不计类别, Recall 自然高 |
| Fault→Rille 混淆 | 分支2 只在线性区域做分类, 干扰减少 |
| Background 98% 压倒 | 分支1 做二分类, 正负样本比大幅改善 |

### 架构设计

```
SwinV2 Backbone (共享, 不改)
    ├── FPN Decoder → [1ch] 分支1: BCE+Dice → 前景/背景
    └── Gate(× sigmoid) → FPN Decoder → [4ch] 分支2: CE(仅GT>0像素) → WR/Rille/Fault/Graben
```

- 分支1 解码器: `smp.UnetDecoder` (轻量, 开源)
- 分支2 用分支1 的 sigmoid 做 attention gate, 只看高概率区域
- 最终输出 = 分支2 × 分支1 (背景自动归零)

### 可复用开源组件

| 组件 | 来源 |
|------|------|
| SwinV2 backbone | 现有代码, 不改 |
| UnetDecoder | `segmentation-models-pytorch` |
| FPN+PAN | 现有 `swinv2unet.py` |
| BCE+Dice Loss | 现有实现 / `smp.losses` |

> 先跑完 R50-53 确认单分支天花板, 再决定是否动手实现.

### 切分策略

| 参数 | 值 | 说明 |

### 区域划分 (地理坐标)

- **Mare Serenitatis**: 按纬度 Y 横切

  - 22.52° < Y ≤ 27.53° → val

- **Rima Ariadaeus**: 按经度 X 竖切
  - X ≤ 14.67° → train
  - 14.67° < X ≤ 17.07° → val
  - X > 17.07° → test
- **其他区域**: 随机 10% val / 90% train
- `test_` 前缀文件 → 强制 test

### v9-256 教训已修复

# 重大方向转折：随机 8:1:1 划分 (2026-08-12)

## 背景：为什么放弃 Scene Split

之前 R46-R55 全部用 Scene Split（空间隔离），单分支 mIoU 卡在 ~0.50，Graben 尤其灾难（0.08-0.36）。

**根因诊断（2026-08-13 修正）**：之前归因于"Graben 域迁移"是错的。实际是补标注时把背景误标为 Graben，导致训练集 Graben 特征被污染。v5 Graben 形态本就一致，现已修复。

**论文定位调整**：不追求"空间泛化"（全月制图），改为"典型研究区线性构造提取能力验证"。参考 Yan et al. (2024, Sensors) 的做法——随机 8:1:1 划分，验证模型能否从相似外观的 tile 中学到提取规则。

## 随机 8:1:1 数据划分

脚本: `scripts/random_split_811.py`

- v5 全部 train(1844) + test(304) = 2148 tiles 合并
- 随机打乱 → 8:1:1: Train 1718 / Val 214 / Test 216

- Kaggle dataset: `changyasong/v5data/datasetv5_random811` (Swin) / `yuanssy/v5data/datasetv5_random811` (DeepLab)

## ⚠️ 重要：Swin vs DeepLab 对比不公平

R56 Swin 用了 `freeze_stages=2`（冻结 patch_embed + 前 2 stage），R57 DeepLab 没冻结（ImageNet 全量微调）。**这个 0.078 的差距有部分是 freeze 造成的，不能下"DeepLab 优于 Swin"的结论。**

要公平对比，Swin 需用 `freeze_stages=0` 重跑。

## 数据泄漏的两层讨论

### 层次 A：区域级不均衡（可解决，应解决）

全局随机 8:1:1 的风险：某区域（如 Rima 的 Graben 区）可能 90% 进 train、10% 进 test → 区域失衡导致域迁移。

**解法：分层随机 8:1:1**——每区域内部先随机 8:1:1，再合并各 split。保证每区域在 train/val/test 都有代表。

### 层次 B：同一构造跨 tile 泄漏（不可避免，写进论文）

v5 切 tile stride=307, tile=512, **40% 重叠**。一条大皱脊跨 20 个 tile，随机分后相邻 tile 可能进不同 split → test 见过 train 的相邻段。

**解法：只有空间隔离（Scene Split）能消除，但那带来域迁移灾难。** 选择承认，写成 limitation：

> 由于 tile 采用 40% 重叠滑动窗口生成，同一构造的相邻 tile 可能分布于不同划分。本文通过分层随机划分保证区域分布均衡，但构造级别相邻 tile 的相关性不可避免，将在讨论中分析。

## 下一步计划

1. **分层随机 8:1:1 脚本**：按区域前缀分组，区域内随机 8:1:1，合并
2. **公平对比**：Swin `freeze_stages=0` 重跑，DeepLab 保持
3. **确认主力模型**：公平对比后再定 Swin vs DeepLab 谁是主模型
4. **分区域分析**：test 按研究区拆 per-class IoU
5. **汽海/云海盲推** + 构造统计 + 应力分析

## 讨论要点（答辩用）

- 研究定位：典型研究区提取能力验证，非全月制图
- 数据：6 个典型地质单元（Serenitatis 月海 / Rima 地堑月溪 / Aristarchus 火山高原 / Marius 火山穹丘 / Orientale 盆地 / Catena 链区）
- 标注策略：高置信度专家标注（只标确认构造），模型"假阳性"可能是漏标真构造 → 标注策略写成论文一部分
- 随机 8:1:1 合法性：Yan et al. (2024) 等大量论文支撑，不同 tile 像素不重叠

## R58 结果：Swin 全量训练 (freeze_stages=0) (2026-08-13)

补充 R56 冻结基线，用 `freeze_stages=0` 全量重跑 Swin，与 DeepLab 公平对比。

| 类 | R56 冻结 Swin | R58 全量 Swin | DeepLab (R57) |
|----|--------------|--------------|---------------|
| Background | 0.9897 | 0.9899 | 0.9937 |
| 皱脊 WR | 0.5458 | 0.5613 | 0.6320 |
| 月溪 Rille | 0.5916 | 0.5913 | 0.6697 |
| 断层 Fault | 0.4670 | 0.4678 | 0.6198 |
| 地堑 Graben | 0.7086 | 0.7223 | 0.7754 |
| **前景 mIoU** | 0.578 | **0.586** | **0.674** |

**结论：freeze_stages 不是主因。** 解除冻结只涨 0.8 点（0.578→0.586），Swin 全量仍比 DeepLab 低 8.8 点。

## 核心发现：Swin patch 化丢细线（创新方向）

per-class 差距与线宽成反比：

| 类 | Swin vs DeepLab 差距 | 线宽 |
|----|---------------------|------|
| 断层 Fault | -0.152 | 最细(1-2px) |
| 月溪 Rille | -0.078 | 细 |
| 皱脊 WR | -0.071 | 中 |
| 地堑 Graben | -0.053 | 最粗 |

**根因**：Swin 的 patch_embed 是 4×4 patch 化，1px 宽的断层在 4×4 patch 里只占 1/16 像素，patch embedding 把细线信号稀释。ResNet50 连续卷积下采样对细线更友好。

**创新方向**：设计模块补上 Swin patch 化丢失的细线细节（高分辨率浅层直连 / 细线感知分支 / 边界加权），目标让全量 Swin 的 Fault/Rille 提升、整体超过 DeepLab 0.674。

## 数据划分最终结论 (2026-08-13)

- 随机 8:1:1 确认可用，定位"构造提取能力"（非空间泛化）
- 文献支撑：Zhang(6:2:2)/Yan(8:1:1)/Lu(8:2)/Li(8:2) 均随机划分
- 稳健性用"5 次随机种子重复"，不用留一区（留一区测跨区泛化，与本定位无关）

# 文献基线对照（2026-08-17 手动查齐，答辩核心依据）

## 4 篇文献真实基线（前景指标）

| 文献 | 构造 | 数据源 | 分辨率 | 任务 | 前景指标 |
|---|---|---|---|---|---|

> 注：Li 的 lobate scarps 正确译法是「叶状陡坎」（非"隆起断层"），它极细极小，必须用 NAC 高分辨率才能看到，所以 Li 用 NAC 是任务必需、非刷分。

## 核心规律：二分类 IoU 由「分辨率 + 数据源」决定

- Li 0.96 = 0.8~5m NAC（叶状陡坎太细，必须 NAC）
- Zhang 0.85 = 100m WAC+DEM（有光学）
- Lu 0.72 = 59m 纯 DEM（无光学，最难）

## 关键对比（答辩核武器）

同数据源（100m WAC+DEM）+ 同类（月溪）：
- Zhang 二分类月溪 IoU **0.85**
- 本工作 5 分类月溪 IoU **0.67**
- 差 0.18 = 5 分类多类混淆的代价（不是模型不行）

## Lu(0.72) vs Zhang(0.85) 差 0.13 的原因

**主因是数据源 + 类别，不是划分比例**：
- 数据源：Lu 纯 DEM（无光学）vs Zhang 有 WAC 光学 → 决定性
- 类别：褶皱岭（低起伏模糊）vs 月溪（暗色河道清晰）→ 重要
- 划分比例：Lu 8:2（训练80%）反而比 Zhang 6:2:2（训练60%）**差** → 证明训练量/划分比例不是瓶颈
- 次要：Zhang 60% 重叠切片 → 泄漏更重 → IoU 更虚高；Lu 无重叠 → 更干净

## 答辩话术

> "二分类文献的前景 IoU 是分辨率决定的：Li 用 0.8m NAC 才 0.96，Lu 用纯 DEM 只有 0.72。我用 100m WAC+DEM 做 5 分类，和 Zhang 同源。Zhang 二分类月溪 0.85，我 5 分类月溪 0.67，差 0.18 正是多类混淆的代价。前景 mIoU 0.674 完全合理。"
